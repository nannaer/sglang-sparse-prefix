# 235B A1/A2 性能差异验证

**已确认：旧两轮实验在路由分歧前，worker 的服务速度就已不同；现存记录不能唯一确定底层原因。** 不能将全部差异归因于 Preble，也不能据此宣称复现了论文性能。
原实验：1727，Qwen3-235B-A22B-Instruct-2507 BF16，8×H200、两组 TP4；393 条相同输入、相同计划到达时间、相同启动配置，全部请求成功。

| 指标 | A1 | A2 |
| --- | ---: | ---: |
| 平均 TTFT（秒） | 28.390 | 14.301 |
| 平均端到端延迟（秒） | 64.747 | 38.109 |
| 未命中输入 token | 1,283,422 | 1,486,460 |
| 最终迁移计数 | 58 | 110 |
| 输出 token | 17,550 | 17,537 |

前 **149** 条请求选择的 worker 完全相同；这部分平均 TTFT 已为 **32.096 / 20.671 秒**，缓存命中比例约 **82.625% / 82.631%**。首次路由分歧为 index149，计划到达 95.361 秒。
冷请求 index0/1 在相同 worker、缓存命中为零且输出 hash 相同时，TTFT 分别为 8.087/4.610、7.995/4.454 秒。正式负载最初尚无活跃 decode 的 prefill 也已显示 A2 更快。

| 会话 | worker0 / worker1 的 16K TTFT（秒） | 32K TTFT（秒） | 外部 warmup 早于内置 ready |
| --- | ---: | ---: | --- |
| 旧 A1 | 6.355 / 6.371 | 15.818 / 15.853 | 否 / 否 |
| 旧 B1/B2 | 6.368 / 3.441 | 15.811 / 9.923 | 否 / 是 |
| 旧 A2 | 3.537 / 3.431 | 10.001 / 9.915 | 是 / 是 |
| 新 2296，双 ready 门禁 | 6.419 / 6.396 | 15.949 / 15.915 | 否 / 否 |

两轮 Preble 的 12 个 warmup 样本输入、缓存/输出 token 数及输入/输出 hash 一致；速度差异在多个 512-token chunk 中持续存在，早于正式负载和前端路由。
旧 runner 仅等 `/server_info` 就启动外部 warmup，确有启动竞态：A2 worker0 的 LF82 已 flush、LF86 已执行外部 prefill，LF104 才打印内置 ready。竞态与六个旧 worker 会话的快慢分组相关，**未证明因果关系**。
新门禁要求两个 worker 的完整 ready 日志及配置检查全部通过，再执行任何 flush/profile；已验证 12 个 profile 与 flush 的开始时间均晚于门禁。ready 包含内置 HTTP warmup 完成和此前本机 TP 初始化完成，代码没有额外的 warmup 后 TP barrier。
新 2296 的 16K/32K warmup 接近旧慢组；跨主机、不同 runtime 的单次观察仍不足以解释旧差异。A2 更早完成请求可能改变反馈和后续路由，但计划到达时间加延迟只是完成时间代理，58/110 次迁移没有逐事件代价轨迹可作因果归因。
输出总数差 13 来自 index113：A1 达 45-token 上限，A2 在 32 token 命中模型允许的 EOS151643；两者成功且未超上下文预算，属于正常 EOS。未保存完整生成 token，无法确定贪心输出为何不同。
缺少历史连续 GPU 时钟/功率/温度、CPU/NUMA 和 kernel/collective profiling，不能给出唯一硬件或后端根因；A1/A2 无 OOM、retraction 或运行异常。仅两轮 Preble 不足以分离服务速度、排队和路由反馈的贡献。
